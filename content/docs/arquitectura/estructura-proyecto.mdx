# Estructura del Proyecto y Organización del Código Fuente

Conozca la estructura organizativa del proyecto Moodify y cómo está estructurado el código fuente para facilitar el mantenimiento y la escalabilidad.

## Estructura General del Directorio

```
moodify-frontend/
├── app/                    # Aplicación Next.js con App Router
├── components/             # Componentes reutilizables de UI
├── content/                # Contenido de documentación
│   └── docs/              # Documentación en formato MDX
├── lib/                    # Lógica compartida y utilidades
├── public/                 # Archivos estáticos públicos
├── scripts/                # Scripts de automatización
├── styles/                 # Estilos globales y configuración
├── types/                  # Definiciones de tipos TypeScript
├── .env.local             # Variables de entorno (no versionado)
├── next.config.mjs        # Configuración de Next.js
├── package.json           # Dependencias y scripts del proyecto
├── pnpm-lock.yaml         # Bloqueo de versiones de dependencias
├── postcss.config.mjs     # Configuración de PostCSS
├── README.md              # Documentación principal del proyecto
├── source.config.ts       # Configuración de Fumadocs
└── tsconfig.json          # Configuración de TypeScript
```

## Directorio `/app` - Aplicación Principal

El corazón de la aplicación Next.js 15 con App Router:

```
app/
├── (auth)/                # Rutas de autenticación
│   ├── login/
│   │   └── page.tsx      # Página de inicio de sesión
│   └── register/
│       └── page.tsx       # Página de registro
├── api/                   # Endpoints de API REST
│   ├── auth/              # Autenticación y autorización
│   ├── history/           # Historial de análisis
│   ├── music/             # Integración con música
│   ├── recommendations/    # Recomendaciones personalizadas
│   └── user/              # Gestión de perfil de usuario
├── dashboard/             # Panel principal del usuario
│   ├── page.tsx           # Página principal del dashboard
│   └── components/        # Componentes específicos del dashboard
├── detect/                # Detección de emociones
│   └── page.tsx           # Página de captura y análisis emocional
├── layout.tsx             # Layout raíz de la aplicación
├── page.tsx               # Página de inicio pública
└── providers.tsx          # Proveedores de contexto global
```

### Patrones de Rutas Especiales

- **`(auth)`**: Grupo de rutas para autenticación sin afectar la URL
- **`[id]`**: Parámetros dinámicos en rutas
- **`[[...slug]]`**: Parámetros catch-all para rutas anidadas
- **`not-found.tsx`**: Páginas 404 personalizadas
- **`error.tsx`**: Manejo de errores por segmento
- **`loading.tsx`**: Estados de carga optimistas

### Principios de Diseño de Componentes

1. **Atomic Design**: Componentes construidos desde átomos hasta organismos
2. **Reutilización Máxima**: Cada componente debe ser usable en múltiples contextos
3. **Tipado Estricto**: Todos los componentes deben tener interfaces TypeScript definidas
4. **Accesibilidad**: Cumplimiento de WCAG 2.1 AA
5. **Responsive Design**: Funcionamiento en todos los tamaños de pantalla

## Directorio `/lib` - Lógica Compartida

Utilidades y servicios compartidos entre toda la aplicación:

```
lib/
├── auth.ts                # Configuración de autenticación NextAuth
├── chartConfig.ts         # Configuración y temas para gráficos
├── emotionDetection.ts    # Lógica de detección de emociones
├── errorHandler.ts         # Manejo centralizado de errores
├── historyService.ts       # Servicios para gestión de historial
├── prisma.ts              # Cliente de Prisma ORM
├── rateLimit.ts           # Limitación de tasa de solicitudes
├── spotify.ts             # Integración con API de Spotify
├── validation.ts          # Esquemas de validación Zod
└── utils.ts               # Funciones de utilidad generales
```

### Servicios Clave

1. **`auth.ts`**: Configuración de proveedores de autenticación y callbacks
2. **`prisma.ts`**: Cliente tipado de Prisma con configuración de conexión
3. **`spotify.ts`**: Wrapper tipado para la API de Spotify con manejo de tokens
4. **`validation.ts`**: Esquemas Zod para validación de datos en toda la aplicación
5. **`chartConfig.ts`**: Configuración común para Chart.js con temas consistentes

## Convenciones de Nomenclatura

### Archivos y Componentes
- **Componentes React**: PascalCase (`UserProfile.tsx`)
- **Hooks personalizados**: `use` + PascalCase (`useAuth.ts`)
- **Utilidades**: camelCase (`formatDate.ts`)
- **Constantes**: UPPER_SNAKE_CASE (`API_ENDPOINTS.ts`)

### Estilos y Clases CSS
- **Clases Tailwind**: Utilizar utilidades de Tailwind CSS
- **Clases personalizadas**: Prefijo con `moodify-` (`moodify-gradient-primary`)
- **Variants**: Utilizar sistema de variants de Tailwind

### Importaciones
- **Alias de ruta**: `@/components/Button` en lugar de `../../components/Button`
- **Importaciones nombradas**: Preferir importaciones específicas
- **Orden de importaciones**: Librerías externas, luego internas, luego locales

Esta estructura organizativa permite un desarrollo escalable, mantenible y colaborativo, siguiendo las mejores prácticas de la industria para aplicaciones modernas de React/Next.js.
